Pull request validation uses three independent jobs: `Rust checks`, `Frontend lint and unit checks`, and `Browser and RSS integration`. The integration job builds the production API and web images with BuildKit caching, then runs the browser and RSS suites against those images without an artifact hop or a rebuild. The Playwright runner is built in the same job. Native Rust checks and frontend lint/component tests run once each in their own jobs. Do not add a second invocation of `npm run typecheck` to the frontend CI sequence: `npm run build` already runs `tsc -b`. Fuzz smoke and extended fuzzing share one workflow and runner, with distinct triggers, duration, and artifact retention; only superseded pull request runs are canceled. Production image scans run in `publish-containers.yml` before publishing. See `docs/ci-workflows.md` for cache keys, invalidation behavior, local image builds, `act` fixture prerequisites, and the branch-protection migration.

## Local verification

Run `cd web && npm ci && npm run check`, `./scripts/check-rust.sh`, and `./scripts/integration-e2e.sh` for the main product checks. Run `shellcheck`, `ruff`, Semgrep, filesystem Trivy, and fuzzing separately when their tools or pinned runtime are available. `./scripts/ui-e2e.sh` and `bash ./scripts/e2e.sh` remain useful for isolating one integration suite; the canonical combined command is `./scripts/integration-e2e.sh`. For prebuilt-image and local cache instructions, see `docs/ci-workflows.md`.
