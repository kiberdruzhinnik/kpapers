# Design

## Context

See proposal.md for motivation. PDF extraction reconstructs styled runs and then groups lines into semantic HTML. Wrapped title joining depends on typography and run style, and cached output is keyed by the PDF processing revision.

## Goals / Non-Goals

**Goals:**
- Keep the supplied headline as one semantic title across its visual lines.
- Preserve the disclaimer's literal asterisks while rendering the complete text in `<strong>` inside its own paragraph.
- Ensure already cached documents are eligible for reprocessing after the parser behavior changes.

**Non-Goals:**
- Change generic bold/italic handling, unrelated cleanup rules, or the safe HTML allowlist.
- Infer bold formatting from arbitrary Markdown syntax throughout article prose.

## Decisions

- Treat the matched disclaimer as literal source text, not Markdown syntax to parse. Keep both `**` pairs in the text and apply bold through the PDF publication styling path. This produces the requested visible markers and semantic bold markup; stripping the markers as Markdown would contradict the required output.
- Keep the disclaimer as a paragraph even if its typography could otherwise make it a heading. Its content and position after the title identify the block.
- Use the existing `<strong>` tag for bold output. It is already part of the pipeline's semantic HTML convention and expresses the same bold emphasis as `<b>`.
- Keep title joining based on the existing PDF layout cues and add coverage for the supplied title. Avoid a filename-specific workaround because the PDF text layer contains the complete headline.
- Increment the PDF processing revision when implementation changes, so cached HTML generated by earlier behavior is refreshed on a later ingestion.

## Risks / Trade-offs

- [A PDF may split the disclaimer text or its asterisks across styled runs] -> Match the reconstructed line text across adjacent runs and preserve styling when emitting the paragraph.
- [Broader Markdown interpretation could alter article text] -> Do not parse these literal markers as Markdown; preserve the requested full span and add regression coverage for unmatched marker text.

## Migration Plan

No database migration is needed. Increment the processing revision so normal refresh processing regenerates cached HTML; if extraction fails, existing cache retention behavior remains in effect.
